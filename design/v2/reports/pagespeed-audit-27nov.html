Laporan audit performa

Website Stillway V2:
Hasil Audit PageSpeed Insights

Tanggal audit: 27 November 2026  ·  Alat: Lighthouse 13.6.0 (mesin PageSpeed Insights)  ·  Disusun oleh tim proyek Stillway
Ringkasan
  • Versi staging (versi terbaru) sudah jauh lebih baik daripada production. Skor Performance naik dari 50 ke 69 di mobile dan dari 71 ke 79 di desktop. Ukuran halaman awal turun sekitar 60% (3,9 MB → 1,6 MB).
  • Tiga dari empat metrik Core Web Vitals utama sudah “Good” di staging: konten pertama tampil 1,1 detik, konten utama tampil 2,1 detik, dan tata letak stabil (CLS 0).
  • Penghambat yang tersisa hanya satu: Total Blocking Time (TBT). Inisialisasi animasi 3D cincin membuat browser sibuk 2,5–4,3 detik di HP, sehingga halaman lambat merespons di detik-detik awal.
  • Accessibility (95–100) dan Best Practices (100) sudah memenuhi target 90+. Skor SEO rendah karena situs sengaja disembunyikan dari mesin pencari selama tahap konsep. Ini bukan masalah teknis.
  • Tindak lanjut sedang berjalan: Developer mengoptimalkan inisialisasi 3D dengan target Performance 90+ di mobile dan desktop, tanpa mengubah tampilan. Setelah itu hasilnya dirilis ke production dan dites ulang di PageSpeed Insights.

3. Temuan utama

Yang sudah membaik di staging

  • LCP mobile 5,95 s → 2,10 s. Konten utama di HP kini tampil dalam batas “Good”.
  • Ukuran halaman awal turun sekitar 60%. Gambar section bawah dimuat saat dibutuhkan (lazy-load), dan gambar hero dikompresi ulang.
  • Tata letak tidak bergeser (CLS 0) di semua perangkat.
  • Server cepat: respons dokumen 50–70 ms.

Yang masih menghambat: TBT

Di HP, main thread browser sibuk sekitar 7,5 detik saat halaman dibuka. 5,2 detik di antaranya untuk menjalankan script, dengan blok terpanjang 400–600 ms. Penyebabnya:

  • Shader 3D cincin di-compile untuk semua section sekaligus.
  • Aset 3D section bawah ikut dimuat di awal (meja S06 477 KB dan peta cahaya EXR).
  • Sekitar 123 KB JavaScript belum terpakai saat halaman dibuka.

4. Catatan di luar performa

  • SEO: situs memasang tag noindex, nofollow agar tidak muncul di Google selama tahap konsep. Skor SEO otomatis turun karena itu. Tag akan dicabut saat situs siap dipublikasikan. Di staging, beberapa error tambahan muncul karena staging dilindungi login Vercel.
  • Accessibility: satu tombol navigasi (“nav CTA”) belum memiliki label untuk pembaca layar. Ini perbaikan kecil yang masuk ke putaran berikutnya.
  • Field data: data pengguna nyata (Chrome UX Report) belum tersedia karena trafik production masih rendah. Semua angka di laporan ini adalah lab data, yaitu simulasi terkontrol.

6. Metode pengujian

  • Alat: Lighthouse 13.6.0 di Google Chrome headless. Ini mesin yang sama dengan PageSpeed Insights.
  • Profil mobile: emulasi Moto G Power, CPU diperlambat 4×, jaringan slow 4G. Profil desktop: preset desktop Lighthouse.
  • Pengulangan: 3 kali per konfigurasi, dan yang dilaporkan adalah median, karena skor Lighthouse bervariasi antar run (contoh production mobile: 39, 63, 50).
  • Versi yang diuji: production stillway-two.vercel.app (commit 182048e, rilis 24 Nov) dan staging dari branch Developer (commit 062e3e4, berisi revisi QA 25–27 Nov).
  • Akses staging: staging dilindungi login Vercel. Pengujian memakai token bypass sementara yang langsung dicabut setelah audit.
